# Подготовка репозитория к эксплуатации

## Итоговая структура

Рабочий код перенесён в устанавливаемый пакет `src/number_search`.
Единственные пользовательские точки входа — CLI `number-search`,
`python -m number_search` и Python API `Recognizer`.
Обучение и скачивание данных выделены в подмодуль `training` и не загружаются
при обычном распознавании. Тесты находятся в `tests`, инструкции — в `docs`.

Выбранная v5 поставляется отдельно в `models/v5`: пять исходных checkpoint,
конфигурация и manifest с SHA-256. Проверяются целостность файлов и совместимость
параметров сети. Загрузка использует `weights_only=True`.

## Очистка

Удалены старые корневые скрипты и альтернативные точки входа, CTC/GRU,
эксперимент направления обхода, разовые исследовательские утилиты,
дубли checkpoint, промежуточные веса и скачанные архивы. Прежний каталог
`artifacts` занимал около 1,8 ГиБ; он больше не требуется рабочему пакету.

Исходные пользовательские `data/train`, `data/valid`, `data/test` сохранены.
Сохранены также 50 контрольных внешних изображений, эталоны, источники,
лицензии, выбранные веса, истории обучения и протоколы исследования.
Для расширенных обучающих данных оставлен manifest с точными revisions,
элементами архивов и SHA-256; кеш восстанавливает команда `prepare-data`.

Исторические отчёты сохранены без изменения. Старые пути внутри них —
сведения о происхождении эксперимента. Текущий отчёт и HTML-галерея
используют новую структуру. Файлы локального окружения, кеши, временные
выходы и пользовательские train/valid/test исключены из Git и Docker-контекста.

## Эксплуатация и проверка

Добавлены `pyproject.toml`, фиксация runtime-зависимостей, сборка wheel/sdist,
Dockerfile с пользователем без root и GitHub Actions для Python 3.12/3.14.
Входные изображения и manifests проверяются, JSON сохраняется атомарно,
ошибки CLI возвращают код 2 и диагностическое сообщение в stderr.

Проверено локально на Windows / Python 3.14 / CPU:

- 29 тестов, включая все 50 контрольных изображений и независимость от имени файла;
- Ruff: линтер и проверка форматирования;
- `pip check`: отсутствуют нарушенные зависимости;
- сборка wheel и sdist;
- установка wheel во временный каталог, импорт и распознавание вне репозитория;
- сборка нового комплекта весов утилитой `tools/package_models.py`.

Все 50 предсказанных строк совпали с исходным протоколом v5.
Качество сохранено: **42/50 = 84%**, CER **6,04%**.
Повторный прогон служит проверкой рефакторинга и не является новой независимой
оценкой. Обучение новых весов при этой подготовке не проводилось.

Docker в локальной среде недоступен; образ не собирался.
Удалённый GitHub Actions workflow не запускался.
